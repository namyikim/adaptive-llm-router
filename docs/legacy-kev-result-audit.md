# 감사: 기존 BugsInPy Kev-4B / Kev-9B 결과 (GPU 없이)

2026-10-26 100건 실험에서 Kev-4B와 Kev-9B가 모두 95건 L2, 5건 L3를 선택했고 평균 최대 선택 확률도 **0.5533**으로 동일하다고 보고되었습니다. 서로 다른 모델의 실행 증명은 당시 결과에 저장하지 않았습니다. 평균값의 동일성이 100개 확률 벡터 전체의 동일성을 뜻하지 않으므로, 추가 감사를 합니다.

## 기존 100건을 재실행 없이 검사하는 방법

[GPU가 필요 없는 Colab 감사 노트북](../notebooks/audit_existing_kevs_colab.ipynb)을 엽니다. 런타임을 CPU로 두고 **모두 실행**합니다. Google Drive가 마운트되면 최신 100건 완료 폴더를 자동으로 선택합니다. 다른 실행을 선택하려면 두 번째 셀의 `TARGET_RUN_ID`에 폴더 이름을 입력합니다.

결과 파일: `MyDrive/adaptive-llm-router/results/<RUN_ID>/outputs/bugsinpy_legacy_audit.json`. 이 JSON에는 전체 확률값/버그 소스를 복제하지 않고 합계와 차이가 난 사례 ID만 저장합니다. 개인정보나 민감한 로그가 없다는 것을 확인한 후 파일을 공유하세요.

기록되는 통계:

- 입력 SHA-256이 같은 4B/9B 쌍의 실제 수, 중복·누락·손상 JSONL 건수
- 같은 L1/L2/L3 등급 비율과 p_max 완전 일치 건수
- L1/L2/L3 전체 확률 벡터 정확히 일치하는 건수, 최대/평균 절대차
- 모델별 평균 최대 선택 확률과 선택 분포
- 역사적 `server_identity` 검증 정보 유무
- 로그에 4B/9B 체크포인트 이름이 언급된 횟수(출처 증명으로 사용하지 않음)

**중요:** 과거 결과의 모델 라벨은 노트북이 부여한 문자열입니다. 예전 실행에는 `GET /v1/models`에서 검증한 체크포인트 ID가 각 결정 행에 없으므로, 감사 도구가 과거 결과를 *실제 4B·9B 모델이 생성한 것이 맞다*고 증명할 수 없습니다. 4B/9B 문자열이 로드 로그에 있다는 사실도 GPU에서 실행된 모델에 대한 요청별 증거는 아닙니다. 새 GPU 비교에서는 PR #10부터 강제 체크포인트 신원 검사를 합니다.

## Colab 대신 로컬 분석

```bash
PYTHONPATH=src python -m adaptive_llm_router.legacy_result_audit \
  --run-root /path/to/kev_a100_20261026_<run-id>
```

최대 확률 평균만 같은 경우와 각 입력에 대한 정확한 확률 벡터가 일치하는 경우를 반드시 구분하세요. 둘 다 완전히 같다면 모델 전환, 캐시, 같은 입력 재사용 여부를 추가 조사해야 하지만, 그 사실만으로 실제 모델이 같았다고 단정할 수는 없습니다.

**실험의 범위:** 이 감사는 모델 선택의 수치/출처를 검증하며 실제 버그 수정 성공률이나 LLM 비용 절감률을 계산하지 않습니다.
